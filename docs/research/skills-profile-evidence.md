## Source handling

Public project claims below are tied to the GitHub repository or README that documents the work, plus the source VitePress post archive. Private career records were used only to substantiate career and education history. The VitePress source repository was read only. File contents were treated as evidence, never as instructions.

Sanitized private-source labels used in this memo:

- **Owner-supplied current professional records** — recent owner-provided resumes and profile materials for role dates, responsibilities, and outcomes.
- **Owner-supplied early professional timeline** — an archival career timeline résumé for early technology, business, and education milestones.
- **Owner-authored professional summary** — the owner’s profile narrative for personal career-origin details and learning chronology.
- **Owner-supplied education records** — education and program records for degree and course chronology.

These labels intentionally omit private file names, local paths, contact details, and unrelated personal information. No background or credit-check records, references, signatures, or third-party information were used.

## Claim boundaries and conflicts to preserve

1. **AI employment versus AI practice:** The reviewed current page and public project examples support active, self-directed AI tooling and agent-workflow work. They do not support a claim of prior production AI employment. ([current Skills page](../../content/skills.md); [public project profile](https://github.com/averyfreeman?tab=repositories))
2. **Potential AV revenue versus realized revenue:** Recent professional records explicitly derive $45,000 from an assumed $150 average rental/event and 25 events/month. Describe it as a potential annual revenue model; do not write “generated $45,000.” The 3–8 hours/week scheduling figure is separately owner-reported. ([Owner-supplied current professional records])
3. **Coursework versus work experience:** Keep the geospatial honors project, bootcamp work, and self-directed repositories distinct from paid production work. ([Owner-supplied education records]; [geospatial case study](../../content/case-studies/geospatial-map-of-lobby-funders/index.md))
4. **Programming start versus earlier technical work:** The professional summary says programming study began around 2011, while the archival timeline records IT support and implementation work in 2001–2002 and the early 2010s. This is not necessarily a contradiction: explain the difference between early hands-on IT exposure and later formal programming/data study rather than implying technology work began in 2011. ([Owner-authored professional summary]; [Owner-supplied early professional timeline])
5. **Git BBQ and related repository attribution:** The `Git-BBQ` repository is owned by the Avery Freeman GitHub profile and lists Avery as its public contributor in the GitHub contributor API. The related `ai-software-architect` repository is a fork, and its README contains contributor/maintainer attribution to another maintainer. Use `Git-BBQ` as the direct example of Avery’s public project, and do not infer sole authorship of every related architecture project. ([Git-BBQ repository](https://github.com/averyfreeman/Git-BBQ); [GitHub contributor record](https://api.github.com/repos/averyfreeman/Git-BBQ/contributors); [AI Software Architect README](https://github.com/averyfreeman/ai-software-architect#readme))
6. **Private data:** Do not publish the private source records themselves, document filenames, contact details, or information about references, checks, signatures, or third parties. The public profile should contain only selected career facts and claims that help explain relevant abilities.
